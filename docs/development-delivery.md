# 开发、实测与 PR 交付

本页适用于本仓的功能、修复和文档修改，规定分支开发、相称验证、草稿 PR 和证据更新流程。

## 开始前
检查 git status、当前分支、git worktree list、远端及同需求已有 PR。保护现有修改和登录状态，不 reset、不静默 stash。
在空闲、干净的开发目录依次执行，每步失败即停止后续步骤：

```powershell
git switch main
git pull --ff-only origin main
git switch -c codex/<任务名>
```

已有同需求 PR 就更新原分支，不另开重复 PR。默认复用固定开发目录；只有确实并行或运行隔离需要时才建 worktree，先查可复用目录。

## 开发与上游借鉴
记录用户目标、输入输出和验收条件。检查当前模块及直接依赖有没有已验证的简化路径，不为优化凑改动。
吸收上游 Issue/PR 前，核对状态、补丁、来源提交、许可、适用边界及本仓是否已有等价能力。
未合并补丁也可借鉴，但必须独立核对和实测；不把“上游写了通过”当成本仓验证。
只读范围、官方高德边界、凭证隔离和失败语义继续生效；不顺带引入发布、点赞、支付等写功能。

## 验证与更新
- 运行与改动相关的测试、ruff 和 git diff --check；改变包资源、依赖或入口时构建 wheel 并做源码目录外安装检查。
- 每次功能或平台行为变化都做相应的真实只读烟测，记录代码 SHA、时间/时区、命令、真实数量、耗时和范围。浏览器用原有专用登录目录并串行访问。
- 登录、验证码或网络挡住实测时，保留准确错误，明确仍未验证的项目；PR 保持草稿，不称实测成功，也不要求用户离开期间立即登录。
- 文档修改做链接、格式及命令检查即可，不为文档强行访问平台。
- 更新 README/合同及脱敏验收记录。区分真实平台结果、离线测试、浏览器 fixture 和历史回放。公开 PR 只放必要统计、自写摘要和公开链接；不上传整篇帖子/评论、cookies、profile、签名 URL 或私密配置。
- 工具包变化先经工具仓 PR 验收；集成仓另用固定 Git SHA 和 uv.lock 验收。未合并版本不能冒充主仓已部署。

## PR 与收尾
使用 Conventional Commit 标题和 .github/PULL_REQUEST_TEMPLATE.md 六段式正文，填写实际验证及未验证项。
完成 commit、push 后创建或更新草稿 PR，并把每个 PR 附到当前聊天。不是占位 PR；必须有具体 diff 和可核验结果。
按 docs/review.md 处理审查意见，每次修复后补验证并更新同一个 PR。
用户明确要求合并前不自行 merge。不要先推 main 再补 PR；不要为追求检查通过降低校验或隐藏错误。
固定开发目录在工作已提交、推送且没有其他修改时回到 main；保留本机配置和验收数据。PR 分支中的功能状态与主分支运行版本分别报告。
