# 当天往返

在主仓环境中使用 `uv run lazy-trip`；安装包后也可用 `lazy-trip`。平台包与主程序共用该环境。默认不固化任何人的城市、住址或口味。

1. 明确城市、区域、具体日期、出发点、时间窗、人数、全组预算、步行上限、交通方式和兴趣。`init` 生成需求草稿，缺失城市/地点需先填写。
2. `research` 串行读取帖子正文、文字评论样本和点评商家。凭证留在专用本地目录；访问令牌只用于内存内详情调用。保留部分失败与已取得证据。实际评论样本数不能写成评论总量；图片未分析时不能声称读过图片。
3. 由当前 AI 阅读证据，提炼 1–6 个候选。标明具体分店、来源 ID、室内外、停留与场内步行估计、消费区间和理由。区分正文事实、评论个人体验、推广/租赁信息和规划估计。
4. `map-tasks --stage search` 生成任务；由宿主 AI 调用当前已连接的官方高德工具，核对 POI 地址/分店、填写 `amapId`；再用 `map-tasks --stage details` 查询详情与天气。不得另行读取 Key。
5. 保存真实 `results:[{id,tool,arguments,receivedAt,result}]`。工具名可以保留宿主命名空间，但对应 `maps_*` 后缀与参数应原样保存。CLI无法证明回执来源，调用者必须保留真实查询。
6. `route-tasks` 生成有向交通段，含返回起点；执行官方工具并追加真实回执。按查询返回的米、秒、元保留单位；不从旧示例冒充当前实测。
7. `plan` 检查时间、全组预算、含场内估计的步行、营业时间、选定分店和返程，输出 JSON 与 HTML。`provisional` 需要核实，不能改写成完全满足。拆分或跨夜营业时间暂不自动验证；超出预报范围、缺字段或旧天气标待更新。
8. 最终说明主方案/室内备选的理由与限制、时间、预计费用和证据，链接实际报告。强降雨时优先考虑延期，并补查官方预警；日预报不能推断逐小时降雨。

第一版仅当天往返；不自动下单、预约、支付。抖音、微博和住宿为后续扩展，官方能力优先，有确认缺口才补自建。
