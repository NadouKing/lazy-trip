# 路线与进度

更新：2026-10-18。以可复现的交付与验收为准，不用“改语言完成”代替产品效果。

| 阶段 | 目标 | 本版范围与验收 |
|---|---|---|
| 1 跑起来 | 当天往返闭环 | 小红书库读取正文/评论样本；官方高德核实商家；AI语义提炼；官方高德地点/天气/路线真实回执；含返程的JSON/HTML与约束检查 |
| 2 部署简单 | 主仓一次安装 | uv锁定主应用与小红书工具，新环境仅clone主仓可sync；Chrome与小红书首次登录有明确步骤；wheel目录外导入和CLI可用 |
| 3 少浪费资源 | 共用主环境、控制浏览器 | 主应用和小红书工具共用一个主venv；串行采集并关闭客户端。缓存、复用CDP会话、减少无效详情查询须基于测量逐项补充，不合并账号profile |
| 4 效果越来越好 | 合适、可信、少折腾 | 任务集比较来源覆盖、关键槽点、分店准确率、天气备选、真实出行反馈和耗时；偏好经用户确认后保存；独立模型宿主另立里程碑 |

原Node/CDP版是已验证基线，Python迁移保留其20项关键行为并补未知/时效校验。各平台真实验收与安装结果记录在交付说明，不把合成测试当作实时平台结果。

点评已完成最后维护并退出路线图，不再安排接口扩展。历史三仓验收保留，当前发布以本轮小红书加官方高德验收为准。

## 后续来源：官方优先，确认缺口后再造工具

以下为2026-10-18核查规划，本次未安装，也不代表当前个人账号已获得权限。官方工具可能另有运行时；不能为了“全Python”重造它。

| 来源 | 路径与限制 | 加入方式 |
|---|---|---|
| 抖音 | [官方MCP能力说明](https://developer.open-douyin.com/docs/resource/zh-CN/dop/ability/mcp-service/mcp-service-desc)有视频/图文搜索文档，但入口能力状态与个人权限需确认；实验/未对外开放不能承诺可用 | 先支持用户分享链接的只读字幕/正文/评论；能授权官方搜索时再接，保留未听取音频/未读图片状态 |
| 微博 | [官方weibo-cli](https://open.weibo.com/cli/quickstart)，需要认证、服务与额度，依赖Node18+ | 优先官方HTTP/CLI适配，Node属于可选官方工具前提；不为统一语言重做官方实现 |
| 携程 | [官方开放平台](https://open.trip.com/?locale=zh-CN)与商旅体系，具体授权与游客只读搜索范围需确认 | 官方可用则优先；否则研究已有浏览器项目，验证日期、房型、人数、取消条件一致后再比价 |
| 去哪儿 | [官方开放合作](https://open.qunar.com/data/detail/open)，[酒店接口文档](https://open.hotel.qunar.com/doc/api-cn.htm)可能是供应商接入，不等于游客可搜索实时价格 | 区分供应商推送和消费者查询；确认缺口后设计只读CDP，价格要有日期、币种、税费与时刻 |
| 美团 | [开发者中心](https://developer.meituan.com/)及联盟商品查询可涉及到餐、酒店、门票，需要申请、AppKey与签名；旅行Skill范围另核实 | 不把营销商品价当最终可订价；先商家补充再住宿，不自动下单 |

住宿加入时扩展多日时间轴、入住退房、交通枢纽和住宿位置优化，不能直接把当天规划的endTime跨到次日。微博/抖音放在证据层；酒店放在独立库存/价格层，保持来源合同。

## 衡量“取长补短”

保留上游可用能力；在同一任务上记录耗时、成功/验证率、证据覆盖、缺字段和查询次数。只有看到瓶颈才改HTTP/CDP/页面函数路径。性能、成本和维护稳定性一起比较，不把Playwright名字或仓库数量当成质量指标。
